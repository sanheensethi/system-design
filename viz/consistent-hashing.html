Consistent Hashing Ring

Every key hashes to a point on a ring [0, 2³²). Each key is stored on the next server clockwise. When you add a server, only the keys between it and the previous server move — not all keys. That's the magic.

Add a server. Add keys. Watch each key snap to the next server clockwise. Now add ANOTHER server — only keys in the slice between old and new server move.

Why "consistent"?

Naive sharding: hash(key) % N. Add a server, N changes, nearly every key relocates — massive data migration.

Consistent hashing: adding a server only affects the arc between it and its predecessor. On average 1/N keys move, not N-1/N.

Used in: DynamoDB, Cassandra, Memcached, Redis Cluster, CDNs.
