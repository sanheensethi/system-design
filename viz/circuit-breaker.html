Circuit Breaker Pattern — Fail Fast

A client calls a downstream Payment Service through a Circuit Breaker. When failures pile up, the breaker trips OPEN and short-circuits subsequent calls — preventing cascading failure. After a cool-down, a single probe tests recovery.

Why Circuit Breaker?

A slow or dead downstream dependency can drag down its callers: threads pile up waiting on timeouts, queues fill, upstream services exhaust resources, and the outage cascades. A circuit breaker fails fast when the downstream is unhealthy — freeing callers to degrade gracefully (serve cached data, show a friendly error, queue the request) instead of hanging.

Choosing Threshold and Timeout

  • Threshold (N): too low → flaps OPEN on transient blips; too high → takes forever to protect callers. Common: 5–10 consecutive failures, or a failure rate over a rolling window (e.g. >50% of the last 20 calls).
  • Timeout: how long OPEN lasts before probing. Must be ≥ the downstream's typical recovery time (restart, GC pause, failover). Common: 5–30 seconds with jitter to avoid thundering herd.
  • Volume guard: don't trip on 2-out-of-2 calls. Require a minimum request volume in the window before evaluating failure rate.

Half-Open Probing

When the timeout expires, the breaker admits one probe call. If it succeeds, the downstream is presumed healthy and the breaker snaps back to CLOSED (counters reset). If the probe fails, the breaker immediately re-opens and the timer restarts. Admitting only one probe prevents flooding a still-recovering service.

Reference Code

class CircuitBreaker:
    def __init__(self, threshold=5, timeout=10):
        self.threshold = threshold
        self.timeout = timeout
        self.state = 'CLOSED'
        self.failures = 0
        self.opened_at = None

    def call(self, fn):
        if self.state == 'OPEN':
            if time.now() - self.opened_at > self.timeout:
                self.state = 'HALF_OPEN'
            else:
                raise CircuitOpenError()
        try:
            result = fn()
            self._on_success()
            return result
        except Exception:
            self._on_failure()
            raise

    def _on_success(self):
        self.failures = 0
        self.state = 'CLOSED'

    def _on_failure(self):
        self.failures += 1
        if self.failures >= self.threshold:
            self.state = 'OPEN'
            self.opened_at = time.now()

Real-World Libraries

  • Netflix Hystrix — the classic JVM implementation (now in maintenance). Introduced circuit breakers to mainstream microservices.
  • Resilience4j — modern, lightweight JVM successor. Composable: CircuitBreaker + Retry + RateLimiter + Bulkhead + TimeLimiter.
  • Polly — .NET resilience library.
  • pybreaker, circuitbreaker — Python options.
  • Envoy, Istio — service-mesh level outlier detection / circuit breaking at the proxy.

When To Use

  • Calls to external dependencies (third-party APIs, payment gateways, email providers).
  • Services known to be slow or flaky, or behind unreliable networks.
  • Any synchronous call on a critical request path where one sick dep can block the whole request.
  • Not needed for pure in-process calls or calls to rock-solid internal dependencies.

Combine With

  • Timeout: prerequisite — without per-call timeouts, a hung request never registers as a failure.
  • Retry + Backoff: retry transient blips inside the breaker. But cap retries so you don't mask real failures.
  • Bulkhead: isolate calls into separate thread/connection pools so one sick dep can't starve the others.
  • Fallback: when the breaker rejects, return a sensible default (cached value, empty list, graceful error) instead of bubbling the exception.
