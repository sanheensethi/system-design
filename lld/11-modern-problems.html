1. Text Editor (Microsoft favorite)

How the pieces talk (inserting a character)
  1. User types 'h' at cursor position 0
  2. UI calls editor.execute(InsertCmd(pos=0, sc=StyledChar('h', style)))   # entry point
  3. Editor.execute calls cmd.do(self)
  4. InsertCmd.do calls ed.buffer.insert(0, sc) → GapBuffer shifts gap, places char
  5. InsertCmd.do sets ed.cursor = pos + 1
  6. execute pushes cmd onto undo_stack, clears redo_stack
  7. execute calls _notify() → for each observer, call on_change(self)
  8. Renderer observer redraws the visible region
  9. User hits Ctrl-Z:
      editor.undo() pops cmd, calls cmd.undo(ed) → buffer.delete(pos) → cursor=pos
      Pushes cmd onto redo_stack, notifies observers
 10. Buffer strategy (GapBuffer vs Rope) is swappable — Editor doesn't care
Requirements
  • Character grid with styling (font family, size, bold, italic).
  • Cursor movement, insert and delete characters.
  • Undo and redo of every operation.
  • Copy, cut, paste across regions.
  • Find and replace (single and all).

Entities: Document, Buffer (Rope / Gap), Cursor, Style, StyledChar, Command (Insert/Delete), History, Clipboard, Finder, Renderer.

v1: Naive list of styled characters

class Style:
    __slots__ = ("font", "size", "bold", "italic")
    def __init__(self, font="Arial", size=12, bold=False, italic=False):
        self.font, self.size, self.bold, self.italic = font, size, bold, italic

class StyledChar:
    __slots__ = ("ch", "style")
    def __init__(self, ch, style): self.ch, self.style = ch, style

class NaiveEditor:
    def __init__(self):
        self.buf = []          # list of StyledChar  -- O(n) insert at middle
        self.cursor = 0
    def insert(self, ch, style):
        self.buf.insert(self.cursor, StyledChar(ch, style))
        self.cursor += 1

# why __slots__: save ~40% memory per char — 1MB doc has 1M chars × ~40B = 40MB vs 70MB
# why StyledChar bundles ch + style: adjacent chars with diff styles coexist
# Break this: list.insert(0, x) on a 1M-element list = 1M memcpy per keystroke = lag
# Usage example — falls over on big docs
ed = NaiveEditor()
s = Style()
for c in "hello":
    ed.insert(c, s)
# Fine for 5 chars. For a 1MB script file:
# Each keystroke at position 0 → O(1M) memcpy → user sees typing lag

Problem: list.insert(i, x) is O(n). For a 1 MB document every keystroke copies a million elements.

v2: Gap buffer for O(1) amortised insertion

class GapBuffer:
    def __init__(self, cap=64):
        self.data = [None] * cap
        self.gap_start = 0
        self.gap_end   = cap        # [gap_start, gap_end) is empty

    def _move_gap(self, pos):
        if pos < self.gap_start:
            n = self.gap_start - pos
            self.data[self.gap_end-n:self.gap_end] = self.data[pos:pos+n]
            self.gap_start -= n; self.gap_end -= n
        elif pos > self.gap_start:
            n = pos - self.gap_start
            self.data[self.gap_start:self.gap_start+n] = self.data[self.gap_end:self.gap_end+n]
            self.gap_start += n; self.gap_end += n

    def insert(self, pos, sc):
        self._move_gap(pos)
        if self.gap_start == self.gap_end:    # grow
            new = [None] * (len(self.data) * 2)
            tail = len(self.data) - self.gap_end
            new[:self.gap_start] = self.data[:self.gap_start]
            new[len(new)-tail:]  = self.data[self.gap_end:]
            self.gap_end = len(new) - tail
            self.data = new
        self.data[self.gap_start] = sc
        self.gap_start += 1

# why gap_start/gap_end: the "hole" moves to the cursor — insertions become O(1) nearby
# why shifting data[gap_end-n:gap_end] = data[pos:pos+n]: moves live chars OVER the gap
#     so the gap now sits at cursor position, ready for fast inserts
# why grow when gap_start == gap_end: gap exhausted → need new buffer (amortized doubling)
# why new[len(new)-tail:] = old[gap_end:]: preserve characters to the RIGHT of the gap
# Break this: move gap far away every keystroke (ping-pong) → O(n) per op, no better than list
# Usage example
gb = GapBuffer(cap=8)
# Initial:  [_, _, _, _, _, _, _, _]  gap=[0,8)
gb.insert(0, StyledChar('h', Style()))
# After:    [h, _, _, _, _, _, _, _]  gap=[1,8)
gb.insert(1, StyledChar('i', Style()))
# After:    [h, i, _, _, _, _, _, _]  gap=[2,8)
gb.insert(0, StyledChar('x', Style()))   # insert at start — gap moves LEFT
# _move_gap(0): slide 'h','i' RIGHT into gap
# After move: [_, _, _, _, _, _, h, i]  gap=[0,6)
# Then insert: [x, _, _, _, _, _, h, i]  gap=[1,6)
GapBuffer state evolution (cap=8):

 initial:           . . . . . . . .        gap=[0,8)  data="........"
 insert(0,'h'):     h . . . . . . .        gap=[1,8)  data="h......."
 insert(1,'i'):     h i . . . . . . .      gap=[2,8)  data="hi......"
 insert(0,'X'):     slide gap to pos 0:
                    step a: move 'h','i' to right end
                    . . . . . . h i        gap=[0,6)
                    step b: place 'X'
                    X . . . . . h i        gap=[1,6)
 when gap fills (gap_start == gap_end):
   - allocate new = [None]*16
   - copy data[:gap_start] to front
   - copy data[gap_end:] to back
   - new gap in middle; continue O(1) inserts

Cost profile:
  consecutive inserts at cursor:      O(1) amortized
  random inserts far from cursor:     O(|cursor - new_pos|) to move gap
  file grows beyond capacity:         O(n) one-time doubling, amortized O(1)
How this breaks in production
  • Ping-pong cursor: user jumps from line 1 to line 10000 to line 1 — gap moves thousands of cells each time, performance drops to O(n). Why: gap-move is O(distance). Fix: Rope data structure for arbitrary-position O(log n) inserts.
  • Indices off-by-one: pos == gap_start branch missing — inserts treated as "move gap" no-op, chars vanish. Why: edge case at gap boundary. Fix: explicit test; assert after move that gap_start == pos.
  • Unicode split: emoji stored as two UTF-16 surrogates → insert between surrogates corrupts char. Why: char ≠ code point. Fix: store grapheme clusters, not UTF-16 units.
  • Delete exposes uninitialized: after delete, data[gap_start..gap_end-1] still holds stale refs → GC can't reclaim. Why: None not assigned. Fix: explicitly set to None in gap range.

v3: Command pattern for undo/redo

class Command:
    def do(self, ed): ...
    def undo(self, ed): ...

class InsertCmd(Command):
    def __init__(self, pos, sc): self.pos, self.sc = pos, sc
    def do(self, ed):   ed.buffer.insert(self.pos, self.sc); ed.cursor = self.pos + 1
    def undo(self, ed): ed.buffer.delete(self.pos);          ed.cursor = self.pos

class Editor:
    def __init__(self):
        self.buffer = GapBuffer(); self.cursor = 0
        self.undo_stack, self.redo_stack = [], []
        self.observers = []
    def execute(self, cmd):
        cmd.do(self); self.undo_stack.append(cmd); self.redo_stack.clear()
        self._notify()
    def undo(self):
        if self.undo_stack:
            c = self.undo_stack.pop(); c.undo(self); self.redo_stack.append(c); self._notify()

# why Command objects (not string log): each command KNOWS how to reverse itself
# why redo_stack.clear() after a fresh execute: new action invalidates redo history — standard UX
# why do/undo symmetry: undo(InsertCmd) = delete; undo(DeleteCmd) = insert — atomic pairs
# why cursor tracked per command: restores EXACT state, not just text
# Break this: command mutates shared state (e.g. sc) between do and undo → undo restores wrong char
# Usage example
ed = Editor()
s = Style()
ed.execute(InsertCmd(0, StyledChar('h', s)))    # undo=[Ins(0,h)]  buf="h"
ed.execute(InsertCmd(1, StyledChar('i', s)))    # undo=[Ins(0,h), Ins(1,i)]  buf="hi"
ed.execute(InsertCmd(2, StyledChar('!', s)))    # buf="hi!"
ed.undo()                                        # buf="hi"  redo=[Ins(2,!)]
ed.undo()                                        # buf="h"   redo=[Ins(2,!), Ins(1,i)]
ed.execute(InsertCmd(1, StyledChar('X', s)))    # buf="hX"  redo CLEARED (new branch)
Stack evolution:

 step 1 execute Ins(0,'h')
   do(): buffer=[h], cursor=1
   undo_stack=[Ins(0,h)]                redo_stack=[]

 step 2 execute Ins(1,'i')
   do(): buffer=[h,i], cursor=2
   undo_stack=[Ins(0,h), Ins(1,i)]      redo_stack=[]

 step 3 execute Ins(2,'!')
   do(): buffer=[h,i,!], cursor=3
   undo_stack=[Ins(0,h), Ins(1,i), Ins(2,!)]

 step 4 undo()
   pop Ins(2,!) → undo(): buffer=[h,i], cursor=2
   undo_stack=[Ins(0,h), Ins(1,i)]      redo_stack=[Ins(2,!)]

 step 5 undo()
   pop Ins(1,i) → undo(): buffer=[h], cursor=1
   undo_stack=[Ins(0,h)]                redo_stack=[Ins(2,!), Ins(1,i)]

 step 6 execute Ins(1,'X')
   do(): buffer=[h,X], cursor=2
   undo_stack=[Ins(0,h), Ins(1,X)]      redo_stack=[]    # cleared — new branch
How this breaks in production
  • Unbounded undo stack: 1M keystrokes in a session → 1M Command objects pinned in memory. Why: no cap. Fix: ring buffer (keep last 1000 commands).
  • Compound operations not grouped: paste of 10K chars pushes 10K commands; 10K Ctrl-Z presses to revert. Why: each char is its own Insert. Fix: CompoundCmd that wraps a sequence, single do/undo.
  • Redo after modification: user undoes, modifies, then hits Ctrl-Y expecting original → gone because redo_stack was cleared. Why: standard UX. Educate users OR implement a tree-history.
  • Non-atomic do: InsertCmd.do crashes halfway (insert succeeds, cursor update raises) → undo won't unwind cleanly. Why: do must be atomic. Fix: wrap in try/except; revert on failure.

v4 + v5: Observer rendering & Memento snapshots

    def _notify(self):
        for o in self.observers: o.on_change(self)

class Memento:
    def __init__(self, ed):
        self.snapshot = list(ed.buffer.as_text()); self.cursor = ed.cursor
    def restore(self, ed):
        ed.buffer = GapBuffer(); [ed.buffer.insert(i, c) for i, c in enumerate(self.snapshot)]
        ed.cursor = self.cursor

# why _notify after every execute/undo: observers (Renderer, StatusBar) stay in sync automatically
# why Memento captures ed.buffer.as_text(): serialization form that's buffer-impl-agnostic
# why list(...): shallow copy of characters — cheap for chars, not for huge docs
# why new GapBuffer + rebuild: simpler than deep-copying internal gap state
# Break this: observer raises in on_change → notify halts → remaining observers stale
# Usage example
ed = Editor(); hist = []
class ConsoleRenderer:
    def on_change(self, ed): print("Redraw:", ed.buffer.as_text())

ed.observers.append(ConsoleRenderer())
ed.execute(InsertCmd(0, StyledChar('h', Style())))  # prints "Redraw: h"
hist.append(Memento(ed))                             # save point 1
ed.execute(InsertCmd(1, StyledChar('i', Style())))  # prints "Redraw: hi"
hist[0].restore(ed); ed._notify()                    # reverts to "h"
Observer flow:
  Editor.execute(cmd)
     │
     ├─ cmd.do(self)                    # mutate buffer + cursor
     ├─ undo_stack.append(cmd)
     ├─ redo_stack.clear()
     └─ _notify()
          for o in self.observers:
             o.on_change(self)         # Renderer re-renders; StatusBar updates "line X col Y"

Memento restore:
  m.restore(ed)
     │
     ├─ ed.buffer = GapBuffer()        # fresh buffer
     ├─ replay each char via insert
     └─ ed.cursor = m.cursor
  (caller must call _notify manually after restore, OR wrap restore inside execute)
How this breaks in production
  • Observer raises: one Renderer throws during on_change — subsequent observers skipped, UI and StatusBar go out of sync. Why: no isolation. Fix: try/except per observer, log and continue.
  • Notify storms: typing fires 100/sec; each calls 5 observers → UI can't keep up. Why: synchronous. Fix: debounce notify by ~16ms (one frame).
  • Memento inconsistent with Command history: restore to past state but undo_stack still holds commands that point at newer chars → ghosts. Why: two undo mechanisms collide. Fix: pick ONE (Command OR Memento) for user-level undo.
  • Deep snapshot on big doc: Memento of a 500 MB doc takes seconds to build. Why: O(n) copy. Fix: copy-on-write buffer (Rope), or snapshot only dirty regions.
Patterns used: Command (undo/redo), Memento (save points), Observer (renderer), Strategy (Rope vs GapBuffer backend).
Edge cases: multi-byte Unicode (combining marks, emoji with ZWJ), selection across mixed styles, very long lines, undo after paste (one command, not N), find-replace interaction with undo.
Extensions: collaborative editing (CRDT / OT), syntax highlighting (tokeniser observer), word-wrap (virtual line layer), persistence (autosave).

2. In-Memory Database (Flipkart, Atlassian)

How the pieces talk (BEGIN / INSERT / ROLLBACK)
  1. Client: txn = Transaction(db); txn.do(InsertOp(table="users", row=Row(pk=42)))
  2. Transaction.do calls op.apply(db) → db.tables["users"].rows[42] = row
  3. Transaction records the op in self.ops (for undo)
  4. Client does 10 more inserts — each appends to self.ops
  5. Client calls txn.savepoint("sp1") → self.savepoints["sp1"] = 10
  6. Client does more ops (ops 11-15), decides to undo them
  7. txn.rollback_to("sp1") → pop ops 15→14→...→11, calling op.revert(db) each
  8. Each revert restores the previous state (InsertOp.revert pops the row)
  9. Client calls txn.commit() → self.active = False — the final state becomes "real"
 10. In MVCC version: reads never see other txn's writes (snapshot_ts gate)
Requirements
  • CREATE/DROP tables with typed columns.
  • INSERT / SELECT / UPDATE / DELETE with WHERE predicates.
  • Transactions: BEGIN, COMMIT, ROLLBACK, nested SAVEPOINT.
  • Secondary indexes for fast lookup.
  • Concurrent transactions with isolation.

Entities: Database, Table, Column, Row, Index, Transaction, TxnLog, Lock, MVCCVersion.

Database
  ├── tables: {name -> Table}
  │         Table ── Column[], Row[], Index[]
  │                  Row ── values + versions[tx_id, value]
  └── txn_manager
           └── Transaction ── ops[], savepoints, snapshot_ts

v1 → v3: From dict to transactional log

class Op:
    def apply(self, db): ...
    def revert(self, db): ...

class InsertOp(Op):
    def __init__(self, table, row): self.table, self.row = table, row
    def apply(self, db):  db.tables[self.table].rows[self.row.pk] = self.row
    def revert(self, db): db.tables[self.table].rows.pop(self.row.pk, None)

class Transaction:
    def __init__(self, db):
        self.db = db; self.ops = []; self.savepoints = {}; self.active = True
    def do(self, op):
        op.apply(self.db); self.ops.append(op)
    def savepoint(self, name): self.savepoints[name] = len(self.ops)
    def rollback_to(self, name):
        target = self.savepoints[name]
        while len(self.ops) > target:
            self.ops.pop().revert(self.db)
    def commit(self):   self.active = False
    def rollback(self):
        while self.ops: self.ops.pop().revert(self.db)
        self.active = False

# why Op with apply/revert: each mutation knows how to undo itself (Command pattern)
# why savepoints stored as LEN of ops at mark time: rollback_to = pop until we reach that index
# why rollback iterates in REVERSE (pop): undo in LIFO order or you get wrong intermediate states
# why commit() just sets active=False: optimistic — no WAL here; in real DB, commit = fsync log
# Break this: op.apply throws mid-execution → half-applied state; next revert corrupts more
# Usage example
db = Database(); db.tables["users"] = Table()
txn = Transaction(db)
txn.do(InsertOp("users", Row(pk=1, name="Alice")))
txn.do(InsertOp("users", Row(pk=2, name="Bob")))
txn.savepoint("after_bob")
txn.do(InsertOp("users", Row(pk=3, name="Charlie")))
txn.do(InsertOp("users", Row(pk=4, name="Dave")))

txn.rollback_to("after_bob")
# reverts Dave, then Charlie — users now {1: Alice, 2: Bob}
# ops stack trimmed to length 2

txn.commit()   # Alice, Bob persist
State evolution:

 t=0   db.tables["users"].rows = {}
       txn.ops = [], savepoints = {}
 t=1   do(InsertOp("users", {pk:1, name:"Alice"}))
       apply: rows = {1: Alice}
       ops = [Ins1]
 t=2   do(InsertOp("users", {pk:2, name:"Bob"}))
       apply: rows = {1: Alice, 2: Bob}
       ops = [Ins1, Ins2]
 t=3   savepoint("after_bob")
       savepoints = {"after_bob": 2}
 t=4   do(InsertOp("users", {pk:3, name:"Charlie"}))
       rows = {1, 2, 3}; ops = [Ins1, Ins2, Ins3]
 t=5   do(InsertOp("users", {pk:4, name:"Dave"}))
       rows = {1, 2, 3, 4}; ops = [Ins1, Ins2, Ins3, Ins4]
 t=6   rollback_to("after_bob")
       target = 2
       pop Ins4 → revert → rows = {1, 2, 3}
       pop Ins3 → revert → rows = {1, 2}
       ops = [Ins1, Ins2]

       active = False; rows = {1: Alice, 2: Bob}

MVCC read isolation:
  Txn A (snapshot_ts=10) reads row pk=42
    row.versions = [(txB, "v1", cts=5), (txC, "v2", cts=15)]
    visible: walks versions in REVERSE, returns FIRST with cts ≤ 10
    → returns "v1" (ignores "v2" because cts=15 > 10)
How this breaks in production
  • Non-reversible op: an op mutates shared state across instances; revert can't fully undo (e.g., external API call). Why: commands aren't always reversible. Fix: forbid external I/O inside txn, or use compensating transactions (saga).
  • Savepoint across commit: commit happens, then rollback_to("sp1") after — operates on empty ops list, NOP but user thinks rollback worked. Why: no validity check. Fix: assert txn.active; raise if committed.
  • Index not updated: InsertOp updates rows dict but skips index.add() → WHERE queries miss the row. Why: dual-write not atomic. Fix: InsertOp updates both; revert removes from both.
  • Write skew under snapshot isolation: two txns read same balances, each withdraws — both succeed, total goes negative. Why: snapshot isolation ≠ serializable. Fix: SSI (Serializable Snapshot Isolation) with read-tracking.

v4: Sorted-list index (stand-in for B-tree)

import bisect
class Index:
    def __init__(self, col): self.col = col; self.keys = []; self.pks = []
    def add(self, key, pk):
        i = bisect.bisect_left(self.keys, key)
        self.keys.insert(i, key); self.pks.insert(i, pk)
    def range(self, lo, hi):
        i = bisect.bisect_left(self.keys, lo); j = bisect.bisect_right(self.keys, hi)
        return self.pks[i:j]

# why two parallel lists (keys, pks): co-sorted — keys[i] always matches pks[i]
# why bisect_left for lo + bisect_right for hi: INCLUSIVE on both ends
# why insert(i, ...) not append: maintains sorted order for next binary search
# Break this: Python list insert is O(n); 1M inserts = 1M² ops = real B-tree needed at scale
# Usage example
idx = Index("age")
idx.add(25, pk=1)    # keys=[25], pks=[1]
idx.add(30, pk=2)    # keys=[25,30], pks=[1,2]
idx.add(28, pk=3)    # keys=[25,28,30], pks=[1,3,2]
idx.add(35, pk=4)    # keys=[25,28,30,35], pks=[1,3,2,4]

idx.range(26, 32)    # bisect_left(26)=1, bisect_right(32)=3 → pks[1:3] = [3, 2]
# ages 28 and 30 → pks 3 and 2

v5 + v6: Per-row locks + MVCC snapshot isolation

class Row:
    def __init__(self, pk): self.pk = pk; self.versions = []   # [(txn_id, data, committed_ts)]
    def visible(self, snapshot_ts):
        for tid, data, cts in reversed(self.versions):
            if cts is not None and cts <= snapshot_ts: return data
        return None

class MVCCTxn:
    def __init__(self, db, ts):
        self.db = db; self.snapshot_ts = ts; self.writes = []
    def read(self, table, pk):
        return self.db.tables[table].rows[pk].visible(self.snapshot_ts)
    def write(self, table, pk, data):
        row = self.db.tables[table].rows.setdefault(pk, Row(pk))
        row.versions.append((id(self), data, None))
        self.writes.append(row)
    def commit(self, commit_ts):
        for row in self.writes:
            for i, (tid, d, cts) in enumerate(row.versions):
                if tid == id(self) and cts is None:
                    row.versions[i] = (tid, d, commit_ts)

# why versions is a LIST of (txn_id, data, commit_ts): append-only log per row
# why cts=None for uncommitted: invisible to other readers until commit stamps a timestamp
# why read walks versions in REVERSE: newest COMMITTED visible wins
# why commit scans versions: stamps all this txn's pending writes atomically (at one ts)
# Break this: forget to check cts is not None in visible() → reader sees uncommitted data
#   (dirty read) — violates isolation
# Usage example — concurrent readers see consistent snapshots
db = Database(); db.tables["users"].rows = {}

tA = MVCCTxn(db, ts=10)           # snapshot at t=10
tA.write("users", 1, {"name": "Alice", "balance": 100})
# Row 1 now has versions=[(idA, Alice, None)]  — uncommitted

tB = MVCCTxn(db, ts=12)           # snapshot at t=12
tB.read("users", 1)               # → None (A's write not committed yet; nothing visible)

tA.commit(commit_ts=14)           # versions=[(idA, Alice, 14)]

tC = MVCCTxn(db, ts=15)
tC.read("users", 1)               # walks versions reversed, 14 ≤ 15 → returns Alice
tB.read("users", 1)               # still None — B's snapshot_ts=12 < commit_ts=14
MVCC timeline for row pk=1:

 t=5   tA writes v1    versions = [(idA, v1, None)]
 t=10  tB reads         visible(10): (idA,v1,None) — None cts → skip; return None
 t=14  tA commits       versions = [(idA, v1, 14)]
 t=15  tC writes v2    versions = [(idA, v1, 14), (idC, v2, None)]
 t=18  tD (ts=16) reads visible(16): reverse iterate
                         (idC,v2,None) skip; (idA,v1,14) 14≤16 → return v1
 t=20  tC commits       versions = [(idA, v1, 14), (idC, v2, 20)]
 t=22  tE (ts=21) reads visible(21): (idC,v2,20) 20≤21 → return v2

Snapshot property: each txn sees a FROZEN view as of its snapshot_ts.
Other txns' concurrent writes are invisible → no phantoms from concurrent inserts.
How this breaks in production
  • Versions list grows forever: 10K updates to one row → versions has 10K entries → read walks them all. Why: no GC. Fix: vacuum removing versions older than oldest active snapshot_ts.
  • Write-write conflict not detected: two txns write same row; last commit wins silently. Why: no conflict check in commit(). Fix: on commit, verify no newer committed version exists since snapshot_ts; abort if so.
  • id(self) collision: a txn object is GC'd; Python reuses its id for a new txn; old versions confused with new. Why: id() is not a unique identifier across lifetimes. Fix: monotonic txn_id counter.
  • Read your own writes: txA writes then reads — expects to see its own write but visible() checks only committed versions. Why: need a "see own uncommitted" path. Fix: visible() prefers versions with tid == id(self) unconditionally.
Patterns: Command (log/undo), Strategy (index type, isolation level), Memento (savepoint), Iterator (result sets).
Edge cases: write skew on serializable, phantom reads, deadlock between two txns, index not updated on UPDATE, NULL comparison semantics.
Extensions: WAL for durability, query planner, foreign keys, triggers, replication.

3. Distributed Task Scheduler (Uber, Swiggy)

How the pieces talk (submitting + executing a task)
  1. Client: scheduler.submit(Task(next_run_at=now+30, fn=send_email, cron="* * * * *"))
  2. submit checks dedupe_key → if seen, drop silently
  3. Under lock: heappush(heap, task) → task placed by next_run_at (min-heap)
  4. cv.notify() wakes loop() thread waiting on empty heap
  5. loop() acquires leader lock (only ONE worker fires tasks)
  6. loop() peeks heap top: if next_run_at > now → cv.wait(timeout=delta)
  7. On wake: heappop task; spawn worker thread for _run_once(task)
  8. _run_once: try task.fn(); on exception → attempt+1, reschedule with backoff
  9. On success: if cron → re-submit with next_after(now); if dedupe_key → add to seen
 10. Failures + retries flow back through submit → heap → loop — cycle continues
Requirements
  • Submit task with delay or cron expression.
  • One-shot or recurring; priority ordering.
  • Retry on failure with exponential backoff.
  • Idempotent execution (at-least-once with dedupe key).
  • Survive worker crashes; exactly one worker fires a given task.

Entities: Task, CronExpr, Scheduler, Worker, Queue (DB-backed), LeaderLock, RetryPolicy.

 submit(task) ──> PriorityQueue [min-heap by next_run_at]
                      │
                  Scheduler loop
                      │  (holds distributed lock)
                      ├── due? ── pop, mark RUNNING in DB
                      ├── execute(task) on worker pool
                      └── on fail  → RetryPolicy.next_delay() → re-enqueue

Core scheduler (~100 lines, Python)

import heapq, time, threading, uuid, random
from dataclasses import dataclass, field
from typing import Callable, Optional

@dataclass(order=True)
class Task:
    next_run_at: float
    priority:    int = 0
    id:          str = field(default_factory=lambda: str(uuid.uuid4()), compare=False)
    fn:          Callable = field(default=None, compare=False)
    cron:        Optional[str] = field(default=None, compare=False)
    max_retries: int = field(default=3, compare=False)
    attempt:     int = field(default=0, compare=False)
    dedupe_key:  Optional[str] = field(default=None, compare=False)

class CronExpr:
    """minimal m h dom mon dow — only '*' and integers supported here."""
    def __init__(self, expr):
        self.fields = [self._parse(f) for f in expr.split()]
    def _parse(self, f): return None if f == '*' else int(f)
    def next_after(self, ts):
        t = int(ts) + 60 - (int(ts) % 60)         # round up to next minute
        while True:
            lt = time.localtime(t)
            m, h, dom, mon, dow = lt.tm_min, lt.tm_hour, lt.tm_mday, lt.tm_mon, lt.tm_wday
            vals = [m, h, dom, mon, dow]
            if all(f is None or f == v for f, v in zip(self.fields, vals)): return t
            t += 60

class RetryPolicy:
    def __init__(self, base=1.0, cap=300.0, jitter=0.2): self.base, self.cap, self.jitter = base, cap, jitter
    def next_delay(self, attempt):
        d = min(self.cap, self.base * (2 ** attempt))
        return d * (1 + random.uniform(-self.jitter, self.jitter))

class LeaderLock:                                 # replace with Redis/ZK in production
    def __init__(self): self._lock = threading.Lock(); self._owner = None
    def acquire(self, who, ttl):
        if self._lock.acquire(blocking=False):
            self._owner = who; return True
        return False
    def release(self): self._owner = None; self._lock.release()

class Scheduler:
    def __init__(self, retry=RetryPolicy(), lock=LeaderLock()):
        self.heap: list[Task] = []
        self.cv   = threading.Condition()
        self.retry, self.lock = retry, lock
        self.seen: set[str] = set()                # idempotency
        self.stopped = False

    def submit(self, task: Task):
        if task.dedupe_key and task.dedupe_key in self.seen: return
        with self.cv:
            heapq.heappush(self.heap, task); self.cv.notify()

    def _run_once(self, t: Task):
        try:
            t.fn()
            if t.dedupe_key: self.seen.add(t.dedupe_key)
            if t.cron:
                t.next_run_at = CronExpr(t.cron).next_after(time.time())
                t.attempt = 0; self.submit(t)
        except Exception:
            if t.attempt < t.max_retries:
                t.attempt += 1
                t.next_run_at = time.time() + self.retry.next_delay(t.attempt)
                self.submit(t)

    def loop(self, worker_id="w1"):
        if not self.lock.acquire(worker_id, ttl=30): return     # only leader fires
        try:
            while not self.stopped:
                with self.cv:
                    while not self.heap and not self.stopped: self.cv.wait()
                    if self.stopped: return
                    now = time.time(); head = self.heap[0]
                    if head.next_run_at > now:
                        self.cv.wait(timeout=head.next_run_at - now); continue
                    task = heapq.heappop(self.heap)
                threading.Thread(target=self._run_once, args=(task,), daemon=True).start()
        finally:
            self.lock.release()

# why @dataclass(order=True): heap uses `<` on Task — order=True auto-generates comparisons
# why compare=False on fn/id/cron: heap compares by next_run_at ONLY, not callable refs (unhashable)
# why LeaderLock: in a cluster, many schedulers run; only one should fire a given task
# why cv.wait(timeout=delta): sleep UNTIL next task due OR until submit wakes us
# why seen set for dedupe: duplicate submissions (retries, cron doubles) are suppressed
# why threading.Thread for _run_once: doesn't block the scheduler loop on long tasks
# Break this: scheduler runs a 5-min task but holds lock with ttl=30s → ANOTHER worker
#   grabs leader mid-task and schedules the same task again → double execution

How this breaks in production
  • Clock skew between workers: worker-1 at t=100, worker-2 at t=130; task scheduled for t=120 runs twice (once by each leader during failover window). Why: timestamps compared across hosts. Fix: trust one clock (DB/Redis), not local time.
  • Leader lock expires mid-task: task runs 60s, lock ttl=30s; second worker takes leader at t=30, pops same tasks. Why: no heartbeat. Fix: renew lock every N seconds while running.
  • seen set grows unbounded: 10M dedupe keys over a week — memory leak. Why: no TTL on dedupe. Fix: LRU cache or Redis with expiration matching task lifetime.
  • Poison task retries forever: an op with a bug throws every time; retry loop burns CPU. Why: no max_retries check before re-submit logic (bug in the code above — attempt < max_retries gate works, but a fix would move exhausted tasks to a DLQ).
Patterns: Strategy (retry policy, lock impl), Command (Task is a command), Singleton (leader), Template Method (loop), Observer (task lifecycle events).
Edge cases: clock skew between workers, DST jumps in cron, dedupe key TTL, poison messages (max_retries exhausted), long-running tasks exceeding lock TTL (need heartbeat renew).
Extensions: priority classes with weighted fair scheduling, task dependency DAG, dead-letter queue, rate-limited queues per tenant.

4. Cache with TTL (Zomato, PhonePe)

How the pieces talk (GET / SET / expire)
  1. Client: cache.set("user:42", obj, ttl=60)                  # entry point
  2. Under lock: check capacity; if full, policy.victim() picks key to evict
  3. Pop victim from store + policy; stats.evict++; notify observers
  4. Create Entry(value, expiry=now+60); store[k] = entry; policy.add(k)
  5. Client: cache.get("user:42")
  6. Under lock: look up entry; if expired → pop, stats.expire++, notify, return None
  7. Else: policy.touch(k) — LRU moves to end; LFU bumps frequency
  8. Background sweeper thread loops: scan store for expired, delete, notify
  9. Policy strategy (LRU / LFU / FIFO) plugged in at construction — Cache doesn't care

  • GET, SET with optional TTL seconds.
  • Lazy + active expiration.
  • Pluggable eviction: LRU, LFU, FIFO.
  • Thread-safe under concurrent access.
  • Stats: hit rate, evictions, expirations.

v3 + v4: LRU + Strategy for eviction

from collections import OrderedDict, Counter
import threading, time

class EvictionPolicy:
    def touch(self, k): ...
    def add(self, k):   ...
    def remove(self, k): ...
    def victim(self):    ...

class LRUPolicy(EvictionPolicy):
    def __init__(self): self.od = OrderedDict()
    def touch(self, k): self.od.move_to_end(k)
    def add(self, k):   self.od[k] = None
    def remove(self, k): self.od.pop(k, None)
    def victim(self):    return next(iter(self.od))

class LFUPolicy(EvictionPolicy):
    def __init__(self): self.freq = Counter()
    def touch(self, k): self.freq[k] += 1
    def add(self, k):   self.freq[k] = 1
    def remove(self, k): self.freq.pop(k, None)
    def victim(self):   return min(self.freq, key=self.freq.get)

class FIFOPolicy(EvictionPolicy):
    def __init__(self): self.q = OrderedDict()
    def touch(self, k): pass
    def add(self, k):   self.q[k] = None
    def remove(self, k): self.q.pop(k, None)
    def victim(self):   return next(iter(self.q))

# why EvictionPolicy is an ABC: Strategy pattern — swap LRU/LFU/FIFO without touching Cache
# why OrderedDict.move_to_end: O(1) in CPython — perfect for LRU touch
# why LFU uses Counter: O(1) increment; O(n) victim search (acceptable unless huge)
# why FIFO.touch does nothing: insertion order is all that matters; never reorder
# why min() with key=self.freq.get: finds least-frequently-used in O(n)
# Break this: wrong policy for access pattern — LFU on a stream of unique keys
#   → nothing is "frequent", victim() essentially random
# Usage example
lru = LRUPolicy()
lru.add("a"); lru.add("b"); lru.add("c")      # od = {a, b, c}
lru.touch("a")                                  # od = {b, c, a}  — a is newest
lru.victim()                                    # "b"  — least recently used

lfu = LFUPolicy()
lfu.add("x"); lfu.add("y")                      # freq = {x:1, y:1}
lfu.touch("x"); lfu.touch("x")                  # freq = {x:3, y:1}
lfu.victim()                                    # "y"  — lowest frequency

v5 + v6: Thread-safe cache with expiry pub/sub

class Entry:
    __slots__ = ("value", "expiry")
    def __init__(self, v, exp): self.value, self.expiry = v, exp
    def expired(self, now): return self.expiry is not None and self.expiry <= now

class Cache:
    def __init__(self, capacity, policy: EvictionPolicy, sweep_interval=1.0):
        self.capacity, self.policy = capacity, policy
        self.store: dict[str, Entry] = {}
        self.lock  = threading.RLock()
        self.stats = {"hit": 0, "miss": 0, "evict": 0, "expire": 0}
        self.subs: list = []
        threading.Thread(target=self._sweep, args=(sweep_interval,), daemon=True).start()

    def set(self, k, v, ttl=None):
        with self.lock:
            now = time.time(); exp = now + ttl if ttl else None
            if k not in self.store and len(self.store) >= self.capacity:
                victim = self.policy.victim()
                self.store.pop(victim); self.policy.remove(victim)
                self.stats["evict"] += 1; self._emit("evict", victim)
            self.store[k] = Entry(v, exp)
            self.policy.add(k)

    def get(self, k):
        with self.lock:
            e = self.store.get(k)
            if e is None: self.stats["miss"] += 1; return None
            if e.expired(time.time()):
                self.store.pop(k); self.policy.remove(k)
                self.stats["expire"] += 1; self._emit("expire", k); return None
            self.policy.touch(k); self.stats["hit"] += 1; return e.value

    def subscribe(self, fn): self.subs.append(fn)
    def _emit(self, ev, k): [fn(ev, k) for fn in self.subs]

    def _sweep(self, interval):
        while True:
            time.sleep(interval); now = time.time()
            with self.lock:
                dead = [k for k, e in self.store.items() if e.expired(now)]
                for k in dead:
                    self.store.pop(k); self.policy.remove(k)
                    self.stats["expire"] += 1; self._emit("expire", k)

# why RLock (re-entrant): if an observer callback calls cache.get → same thread reacquires lock
# why sweeper thread is daemon=True: dies with the process, no shutdown dance
# why Entry.expired check on GET (not just sweep): LAZY expiration — correctness regardless of sweep cadence
# why we evict BEFORE insert (if at capacity): keeps invariant `len(store) ≤ capacity`
# why observers receive (event, key): hooks for metrics, cascade invalidation, etc.
# Break this: observer callback does cache.set (nested lock ok with RLock, but RECURSIVE MUTATION during eviction → confused state)
# Usage example
cache = Cache(capacity=3, policy=LRUPolicy(), sweep_interval=0.5)

def on_event(ev, k): print(f"{ev}: {k}")
cache.subscribe(on_event)

cache.set("a", 1, ttl=5)
cache.set("b", 2, ttl=2)
cache.set("c", 3)                       # no TTL
print(cache.get("a"))                   # 1 (hit, LRU moves 'a' to end)
cache.set("d", 4)                       # capacity full → evict LRU victim = 'b'
# prints: "evict: b"

# After 2+s:  sweeper finds 'b' expired (but already evicted); nothing to do
# After 5+s:  sweeper finds 'a' expired → removes, prints "expire: a"
print(cache.stats)   # {"hit": 1, "miss": 0, "evict": 1, "expire": 1}

How this breaks in production
  • Cache stampede: popular key expires; 1000 requests concurrently miss, all hit DB, then all SET. Why: no single-flight. Fix: per-key lock on miss, or probabilistic early expiration (refresh before TTL).
  • Slow subscriber blocks cache: observer.on_event does a remote call → holds cache lock for 100ms → all GETs queue. Why: synchronous emit under lock. Fix: emit after releasing lock, or deliver via queue.
  • Sweeper holds lock too long: 10M entries, sweeper scans under lock for seconds → whole cache frozen. Why: O(n) scan inside lock. Fix: segmented sweep (1/60th of keys per tick), or expiry heap.
  • TTL=0 ambiguity: some APIs treat 0 as "never expire", others as "immediately expired". Why: underspecified. Fix: explicit policy — None = never, 0 = invalid (raise).
Patterns: Strategy (eviction), Observer (pub/sub), Template Method (sweeper).
Edge cases: TTL of zero, SET on existing key keeps or resets expiry? Negative TTL, clock going backwards, stampede on hot key expiry (use probabilistic early expiration), subscriber slow → blocks cache.
Extensions: tiered cache (L1 in-proc + L2 Redis), write-through vs write-back, sharded lock striping, approximate LFU (Redis style) with decay.

5. Pub/Sub Event System (Razorpay, Paytm)

How the pieces talk (subscribe + publish + deliver)
  1. Subscriber registers pattern: trie.subscribe("order.*", sub1)
  2. TopicTrie walks parts: inserts node "order" → node "*"; appends sub1
  3. Publisher: broker.publish("order.created", msg)                # entry point
  4. trie.match("order.created") walks parts ["order", "created"]:
      - matches literal children first, then wildcard * nodes, then # catch-all
  5. Returns list of matching Subscriptions [sub1, sub2]
  6. For each sub: sub.enqueue(msg)
  7. sub.enqueue applies filter_fn; if false, drop
  8. If queue full → backpressure strategy (drop_oldest / buffer / block)
  9. Worker thread drains queue → invokes sub.cb(msg)
 10. Consumer acks → sub.ack(offset); broker may delete from durable store
Requirements
  • Topics; subscribe, unsubscribe, publish.
  • Wildcard subscriptions: order.*, payments.#.
  • Per-subscriber filter predicate.
  • At-least-once delivery with durable per-subscriber queue and offsets.
  • Backpressure strategy when subscribers lag.

Entities: Broker, Topic, Subscription, SubscriberQueue, Message, TopicTrie.

Topic trie + filter + at-least-once

class TrieNode:
    def __init__(self): self.children = {}; self.subs: list = []

class TopicTrie:
    def __init__(self): self.root = TrieNode()
    def subscribe(self, pattern, sub):
        node = self.root
        for part in pattern.split('.'):
            node = node.children.setdefault(part, TrieNode())
        node.subs.append(sub)
    def _walk(self, node, parts, i, out):
        if i == len(parts):
            out.extend(node.subs); return
        part = parts[i]
        if part in node.children:  self._walk(node.children[part],  parts, i+1, out)
        if '*'  in node.children:  self._walk(node.children['*'],   parts, i+1, out)
        if '#'  in node.children:  out.extend(node.children['#'].subs)   # multi-level
    def match(self, topic):
        out = []; self._walk(self.root, topic.split('.'), 0, out); return out

class Subscription:
    def __init__(self, sub_id, callback, filter_fn=None, backpressure="buffer"):
        self.id, self.cb, self.filter = sub_id, callback, filter_fn
        self.queue: list = []        # durable: persist to disk in prod
        self.offset = 0
        self.backpressure = backpressure  # "buffer" | "drop_oldest" | "block"
        self.max_q = 10_000

    def enqueue(self, msg):
        if self.filter and not self.filter(msg): return
        if len(self.queue) >= self.max_q:
            if   self.backpressure == "drop_oldest": self.queue.pop(0)
            elif self.backpressure == "block":       return "BLOCK"
        self.queue.append(msg)

    def ack(self, offset): self.offset = max(self.offset, offset)

# why a trie keyed on '.' parts: matches "order.created" efficiently — O(parts), not O(subs)
# why '*' matches SINGLE level and '#' matches MULTI-LEVEL: MQTT-compatible semantics
# why filter_fn is per-subscription: one subscriber for "order.*" but only interested in amount>100
# why backpressure "drop_oldest": favours freshness (stock prices); "block" gives flow control
# why ack advances offset: receiver-driven delivery — broker knows what's already consumed
# Break this: publisher does sub.cb() inline (not via queue) → one slow subscriber blocks publish

for s in matches: s.enqueue({"amt": 99})

                            filter_fn=lambda m: m.get("amt", 0) > 100)

How this breaks in production
  • Slow subscriber backs up publish: no queue → publish blocks on slow callback. Why: sync delivery. Fix: per-subscription queue + dedicated worker thread/task.
  • Unbounded queue: subscriber goes down; queue grows until OOM. Why: no max_q enforcement. Fix: bounded queue + backpressure (drop_oldest / block / DLQ).
  • Redelivery after crash: worker crashed after callback but before ack → broker redelivers → double-handling. Why: at-least-once. Fix: idempotent consumer or dedupe store keyed on message id.
  • Order not preserved: two threads publish to "order.*" concurrently; deliveries interleave. Why: no per-key ordering. Fix: partition queue by message key (same key → same worker).
Patterns: Observer (core), Strategy (backpressure), Composite (topic trie), Specification (filter predicates).
Edge cases: unsubscribe while delivering, duplicate delivery (idempotent consumer needed), ordering across topics is NOT guaranteed, only per-topic, queue growth unbounded for slow subscribers, crash between deliver and ack (redelivery).
Extensions: exactly-once via idempotency key + dedupe store, consumer groups (Kafka-style), replay from offset, schema registry.

Interval tree conflict detection + RRULE expansion

from datetime import datetime, timedelta
import bisect

class IntervalTree:
    """Ordered list variant — fine up to a few thousand intervals per room."""
    def __init__(self): self.starts, self.ends = [], []
    def add(self, s, e):
        i = bisect.bisect_left(self.starts, s)
        self.starts.insert(i, s); self.ends.insert(i, e)
    def overlaps(self, s, e):
        i = bisect.bisect_right(self.starts, e)
        for k in range(i):
            if self.ends[k] > s: return True
        return False

class RRule:
    """FREQ=DAILY;COUNT=5 etc. simplified subset."""
    def __init__(self, freq, count=None, until=None, interval=1):
        self.freq, self.count, self.until, self.interval = freq, count, until, interval
    def expand(self, start):
        step = {"DAILY": timedelta(days=1), "WEEKLY": timedelta(weeks=1)}[self.freq]
        out, cur, n = [], start, 0
        while True:
            out.append(cur); n += 1
            if self.count and n >= self.count: break
            cur = cur + step * self.interval
            if self.until and cur > self.until: break
            if n > 10_000: break              # safety
        return out

class RoomAssigner:                                   # Strategy
    def pick(self, rooms, start, end, capacity): ...

class SmallestFit(RoomAssigner):
    def pick(self, rooms, start, end, capacity):
        viable = [r for r in rooms if r.capacity >= capacity and not r.tree.overlaps(start, end)]
        return min(viable, key=lambda r: r.capacity) if viable else None

# why bisect_right(starts, e) as upper bound: any interval that STARTS after our end can't overlap
# why scan k in range(i): any interval with start≤e AND end>s overlaps — linear scan within bound
# why `step * self.interval`: RRULE "interval=2" means every 2nd day
# why `if n > 10_000: break`: DoS guard — a rogue RRULE could expand infinitely
# why SmallestFit picks MIN capacity: don't waste a 100-seat room on a 2-person standup
# Break this: RoomAssigner that reads tree in one thread while another thread adds →
#   overlap check races with add → two meetings accepted into same slot

from abc import ABC, abstractmethod

class OrderState(ABC):
    @abstractmethod
    def next(self, order): ...
    def can_cancel(self): return True

class Placed(OrderState):
    def next(self, o): o.state = Accepted()
class Accepted(OrderState):
    def next(self, o): o.state = Preparing()
class Preparing(OrderState):
    def next(self, o): o.state = OutForDelivery()
class OutForDelivery(OrderState):
    def next(self, o): o.state = Delivered()
    def can_cancel(self): return False      # too late
class Delivered(OrderState):
    def next(self, o): raise RuntimeError("terminal")
    def can_cancel(self): return False

class PartnerAssigner(ABC):
    @abstractmethod
    def pick(self, partners, order): ...

class NearestPartner(PartnerAssigner):
    def pick(self, partners, order):
        return min((p for p in partners if p.available),
                   key=lambda p: p.distance_to(order.restaurant), default=None)

class RatingWeighted(PartnerAssigner):
    def pick(self, partners, order):
        cand = [p for p in partners if p.available and p.rating >= 4.0]
        return min(cand, key=lambda p: p.distance_to(order.restaurant) / max(p.rating, 1e-3),
                   default=None)

class CancelCmd:
    def __init__(self, order, payment_gw, notifier):
        self.order, self.pg, self.notifier = order, payment_gw, notifier
    def execute(self):
        if not self.order.state.can_cancel(): raise RuntimeError("cannot cancel")
        self.order.state = Cancelled()
        if self.order.paid: self.pg.refund(self.order.payment_id)
        if self.order.partner: self.order.partner.release()
        self.notifier.notify(self.order.customer, "order_cancelled", self.order.id)

class PaymentFactory:
    @staticmethod
    def create(kind):
        return {"upi": UPI(), "card": Card(), "wallet": Wallet(), "cod": COD()}[kind]

class BallOutcome:
    runs = 0; legal = True; wicket = False; extra_type = None
    def apply(self, innings):
        innings.score += self.runs
        if self.legal: innings.balls += 1
        if self.runs % 2 == 1: innings.swap_strike()
        if self.wicket: innings.wickets += 1

class Dot(BallOutcome): pass
class Runs(BallOutcome):
    def __init__(self, r): self.runs = r
class Four(BallOutcome): runs = 4
class Six(BallOutcome):  runs = 6
class Wide(BallOutcome): runs = 1; legal = False; extra_type = "wide"
class NoBall(BallOutcome): runs = 1; legal = False; extra_type = "no_ball"
class Wicket(BallOutcome): wicket = True

class Innings:
    def __init__(self, batting, bowling, overs_limit):
        self.batting, self.bowling, self.overs_limit = batting, bowling, overs_limit
        self.score = 0; self.wickets = 0; self.balls = 0
        self.on_strike, self.non_strike = batting.players[0], batting.players[1]
        self.bowler = bowling.bowlers[0]
        self.ball_log: list = []
        self.observers: list = []

    def swap_strike(self): self.on_strike, self.non_strike = self.non_strike, self.on_strike

    def record(self, outcome: BallOutcome):
        outcome.apply(self)
        self.ball_log.append(outcome)
        if self.balls % 6 == 0 and self.balls > 0:
            self.swap_strike()           # over end: strike rotates
        for o in self.observers: o.on_ball(self, outcome)

    def undo(self):
        if not self.ball_log: return
        last = self.ball_log.pop()
        self.score -= last.runs
        if last.legal: self.balls -= 1
        if last.wicket: self.wickets -= 1
        if last.runs % 2 == 1: self.swap_strike()    # reverse strike flip
        if (self.balls + 1) % 6 == 0: self.swap_strike()   # reverse over-end flip
        for o in self.observers: o.on_undo(self, last)

class Spec:
    def is_satisfied(self, ctx): ...
    def __and__(self, o): return And(self, o)
    def __or__(self, o):  return Or(self, o)
    def __invert__(self): return Not(self)

class And(Spec):
    def __init__(self, a, b): self.a, self.b = a, b
    def is_satisfied(self, ctx): return self.a.is_satisfied(ctx) and self.b.is_satisfied(ctx)
class Or(Spec):
    def __init__(self, a, b): self.a, self.b = a, b
    def is_satisfied(self, ctx): return self.a.is_satisfied(ctx) or self.b.is_satisfied(ctx)
class Not(Spec):
    def __init__(self, s): self.s = s
    def is_satisfied(self, ctx): return not self.s.is_satisfied(ctx)

class HasPermission(Spec):
    def is_satisfied(self, ctx): return ctx.prefs.allows(ctx.notif.type)
class InQuietHours(Spec):
    def is_satisfied(self, ctx): return ctx.prefs.quiet_hours.contains(ctx.now)
class ChannelEnabled(Spec):
    def __init__(self, ch): self.ch = ch
    def is_satisfied(self, ctx): return ctx.prefs.channels.get(self.ch, False)
class GlobalDND(Spec):
    def is_satisfied(self, ctx): return ctx.prefs.dnd

class ChannelStrategy:
    def send(self, notif, user): raise NotImplementedError

class EmailCh(ChannelStrategy):
    def send(self, n, u): return gateway.email(u.email, n.render_email())
class PushCh(ChannelStrategy):

class SMSCh(ChannelStrategy):

class FallbackChain:
    def __init__(self, channels): self.channels = channels
    def deliver(self, notif, user, prefs):
        for ch_name in self.channels:
            if not prefs.channels.get(ch_name, False): continue
            try:
                ok = {"push": PushCh(), "email": EmailCh(), "sms": SMSCh()}[ch_name].send(notif, user)
                if ok: return ch_name
            except Exception: continue
        return None

def should_send(notif, prefs, now):
    spec = HasPermission() & ~InQuietHours() & ~GlobalDND()
    ctx  = type("Ctx", (), {"prefs": prefs, "notif": notif, "now": now})
    return spec.is_satisfied(ctx)

# why spec combinators (&, |, ~): rule logic reads like English, composes unit-tested atoms
# why Spec is per-user context ctx: prefs vary per user; rules don't
# why FallbackChain LOOPS channels: if push fails, next try email, etc. — resilience
# why `if not prefs.channels.get(ch_name, False): continue`: respect user's wishes —
#   even if fallback reaches email, skip if user disabled email
# why `except Exception: continue`: ONE channel failure shouldn't kill delivery
# Break this: channel send() returns True even on silent failure → chain stops after "success"
#   user never gets the notification

  • Quiet hours timezone: user travels; quiet hours stored in their HOME timezone but notifications arrive in UTC → midnight in London is not quiet for them in Tokyo. Why: tz mismatch. Fix: store TZ with quiet hours; convert before comparing.

10. Rate Limiter — Multi-Algorithm (Razorpay, PhonePe, Stripe-like)

How the pieces talk (decorating an endpoint)
  1. App startup: algo = TokenBucket(capacity=10, refill_per_sec=5)
  2. @limit(algo=algo, key_fn=lambda req: req.user_id) decorates api()
  3. wrapper(req) called on every incoming request
  4. key_fn(req) extracts bucket key ("user:42")
  5. algo.acquire("user:42") → Decision(allowed, remaining, retry_after)
  6. TokenBucket: lock → refill since last_ts → try take 1 token
  7. If allowed=False → return {"status": 429, "Retry-After": X} IMMEDIATELY
  8. If allowed → call fn(req) → response; attach X-RateLimit-Remaining header
  9. Distributed mode: algo is a thin wrapper over Redis Lua script (atomic check+update)
 10. Swap algorithms (TokenBucket → SlidingWindowCounter) by passing a different instance
Requirements
  • Pluggable algorithms: token bucket, leaky bucket, fixed window, sliding window counter, sliding window log.
  • Dimensions: per-user, per-IP, per-API-key, per-endpoint.
  • Distributed across hosts (Redis).
  • Decorator to wrap any endpoint.
  • Return informative headers (X-RateLimit-Remaining, Retry-After).

Entities: RateLimiter, Algorithm, KeyExtractor, RedisStore, Decision.

import time, collections, threading

class Decision:
    __slots__ = ("allowed", "remaining", "retry_after")
    def __init__(self, allowed, remaining=0, retry_after=0.0):
        self.allowed, self.remaining, self.retry_after = allowed, remaining, retry_after

class Algorithm:
    def acquire(self, key) -> Decision: ...

class TokenBucket(Algorithm):
    def __init__(self, capacity, refill_per_sec):
        self.cap, self.rate = capacity, refill_per_sec
        self.state = {}              # key -> (tokens, last_ts)
        self.lock = threading.Lock()
    def acquire(self, key):
        with self.lock:
            now = time.time(); tokens, last = self.state.get(key, (self.cap, now))
            tokens = min(self.cap, tokens + (now - last) * self.rate)
            if tokens >= 1:
                self.state[key] = (tokens - 1, now)
                return Decision(True, int(tokens - 1))
            self.state[key] = (tokens, now)
            return Decision(False, 0, (1 - tokens) / self.rate)

class LeakyBucket(Algorithm):
    def __init__(self, capacity, leak_per_sec):
        self.cap, self.rate = capacity, leak_per_sec
        self.state = {}              # key -> (water, last_ts)
        self.lock = threading.Lock()
    def acquire(self, key):
        with self.lock:
            now = time.time(); water, last = self.state.get(key, (0, now))
            water = max(0, water - (now - last) * self.rate)
            if water + 1 <= self.cap:
                self.state[key] = (water + 1, now)
                return Decision(True, int(self.cap - water - 1))
            self.state[key] = (water, now)
            return Decision(False, 0, (water + 1 - self.cap) / self.rate)

class FixedWindow(Algorithm):
    def __init__(self, limit, window_sec):
        self.limit, self.win = limit, window_sec
        self.state = {}              # key -> (window_id, count)
        self.lock = threading.Lock()
    def acquire(self, key):
        with self.lock:
            wid = int(time.time() // self.win)
            cur_wid, count = self.state.get(key, (wid, 0))
            if cur_wid != wid: count = 0
            if count < self.limit:
                self.state[key] = (wid, count + 1)
                return Decision(True, self.limit - count - 1)
            return Decision(False, 0, self.win - (time.time() % self.win))

class SlidingWindowLog(Algorithm):
    def __init__(self, limit, window_sec):
        self.limit, self.win = limit, window_sec
        self.state: dict = collections.defaultdict(collections.deque)
        self.lock = threading.Lock()
    def acquire(self, key):
        with self.lock:
            now = time.time(); dq = self.state[key]
            while dq and dq[0] <= now - self.win: dq.popleft()
            if len(dq) < self.limit:
                dq.append(now)
                return Decision(True, self.limit - len(dq))
            return Decision(False, 0, dq[0] + self.win - now)

class SlidingWindowCounter(Algorithm):
    """Approximate: weighted blend of current + previous fixed window."""
    def __init__(self, limit, window_sec):
        self.limit, self.win = limit, window_sec
        self.state = {}              # key -> (wid, prev_count, cur_count)
        self.lock = threading.Lock()
    def acquire(self, key):
        with self.lock:
            now = time.time(); wid = int(now // self.win); frac = (now % self.win) / self.win
            cwid, prev, cur = self.state.get(key, (wid, 0, 0))
            if cwid != wid:
                prev = cur if cwid == wid - 1 else 0; cur = 0; cwid = wid
            est = prev * (1 - frac) + cur
            if est < self.limit:
                cur += 1; self.state[key] = (cwid, prev, cur)
                return Decision(True, int(self.limit - est - 1))
            self.state[key] = (cwid, prev, cur)
            return Decision(False, 0, (1 - frac) * self.win)

# why TokenBucket refills continuously: allows bursts up to capacity, smooths long-term rate
# why LeakyBucket FILLS up (water): serves as a shaper — strict constant output rate
# why FixedWindow has boundary problem: 2× limit possible across window edges (see diagram)
# why SlidingWindowLog is exact but expensive: stores EVERY timestamp — O(N) memory per key
# why SlidingWindowCounter interpolates: approximate (~99% accurate), O(1) memory
# why self.lock around all state: check-and-update must be atomic under contention
# Break this: omit lock → 10 threads each see tokens≥1, all consume → 10× over limit

How this breaks in production
  • Distributed inconsistency: in-memory state across 3 hosts → each allows 10 → 30 per user. Why: local state. Fix: Redis-backed (Lua script ensures atomic check+update).
  • Clock skew in Lua: pass client time as ARGV → attacker sends now=0 → unlimited tokens. Why: trust client. Fix: use redis.call('TIME') server-side.
  • Key cardinality explosion: per-IP limiting during a DDoS → millions of keys, Redis OOM. Why: unbounded keyspace. Fix: EXPIRE on keys; bucket IPs into /24 prefixes.
  • Rate-limited retries: client gets 429, retries in 100ms, retries again, hits same 429 → burn your CPU printing 429s. Why: no Retry-After respect. Fix: honor Retry-After; circuit-break the client.

Distributed token bucket — Redis Lua script

LUA_TOKEN_BUCKET = """
local key = KEYS[1]
local cap = tonumber(ARGV[1])
local rate= tonumber(ARGV[2])
local now = tonumber(ARGV[3])
local data = redis.call('HMGET', key, 'tokens', 'ts')
local tokens = tonumber(data[1]) or cap
local ts     = tonumber(data[2]) or now
tokens = math.min(cap, tokens + (now - ts) * rate)
local allowed = 0
if tokens >= 1 then
  tokens = tokens - 1; allowed = 1
end
redis.call('HMSET', key, 'tokens', tokens, 'ts', now)
redis.call('EXPIRE', key, math.ceil(cap / rate) + 1)
return {allowed, tokens}
"""

def limit(algo, key_fn):
    def deco(fn):
        def wrapper(req, *a, **kw):
            d = algo.acquire(key_fn(req))
            if not d.allowed:
                return {"status": 429, "Retry-After": round(d.retry_after, 2)}
            resp = fn(req, *a, **kw)
            resp["X-RateLimit-Remaining"] = d.remaining
            return resp
        return wrapper
    return deco

# why Lua script atomic: HMGET + compute + HMSET happen as one Redis op — no races across shards
# why ARGV[3] is now (passed in): Lua has `redis.call('TIME')` too, but tests want deterministic clock
# why EXPIRE math.ceil(cap/rate)+1: auto-cleanup idle keys (no traffic → bucket expires)
# why the decorator takes algo as a param: Strategy — one decorator, any algorithm
# Break this: Lua script updated mid-flight but old script cached on some Redis nodes
#   → inconsistent limits per node → unfair user experience
# Usage example

Patterns: Strategy (algorithm), Decorator (endpoint wrap), Template Method (acquire skeleton), Singleton (shared limiter), Proxy (Redis-backed remote algorithm).
Edge cases: clock skew in distributed mode (use server time inside Lua), thundering herd at window boundary (fixed window problem — prefer sliding), burst of 2 × limit across boundary (fixed window flaw), limit changes at runtime (hot config), key cardinality explosion (per-IP DDoS).
Extensions: tenant-tiered limits (free/pro/enterprise), adaptive limits via queue length, concurrency limiter (semaphore variant), cost-based (weighted requests), global vs per-region pools.

Interview Strategy

Opening 5 minutes — clarify requirements

Five questions to ask for ANY LLD problem:

  1. Scale: how many users, requests per second, data size? (drives choice of data structures — in-memory vs. persistent, dict vs. trie.)
  2. Read vs write ratio: tells me where to cache and what to index.
  3. Concurrency model: single-threaded, multi-threaded, or distributed? (Thread safety is the number one thing juniors miss.)
  4. Persistence: does state survive a restart? crash recovery? (changes everything — DB, WAL, snapshots.)
  5. What is out of scope? Say this out loud so the interviewer and you agree (e.g. "I will not implement authentication today").

Middle 30 minutes — entities, diagram, code

  1. List the nouns in the problem statement. Those are your classes (usually 5-8).
  2. Draw the class diagram on the whiteboard — boxes with attributes and methods, arrows for "has-a" and "is-a". Point to it while you talk.
  3. Identify patterns: state machine? strategy? observer? Write one sentence justifying each — do not just name-drop.
  4. Code the hot path first: if it's a cache, write get/set before stats. If it's an order system, write placeOrder before ratings.
  5. Stub what you don't need yet: def payment_gateway(): pass # pluggable — interviewer will appreciate that you know where extension points go.

Closing 10 minutes — edge cases, extensibility, concurrency

  • Walk through 3-4 edge cases proactively (don't wait to be asked).
